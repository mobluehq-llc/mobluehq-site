blueRecall manual

Given a defective reagent lot, a stale calibration, or a software defect, traces the dependency graph in a lab run manifest and signs a per-claim verdict — REVOKED, RERUN-REQUIRED, DEGRADED, UNAFFECTED, or CANNOT-CERTIFY — plus the smallest rerun set that restores what's affected.

What this product is and is not

Is: Reverse impact when an input goes bad.

Is not: No automatic deletion, retraction, notification, or production-system write, and no claim that an unaffected result is scientifically true.

Who uses it

Lab and research-integrity reviewers.

Getting started — the local demo

From the product's own repository:

make demo
make verify-demo

This runs entirely offline against synthetic fixtures and exits non-zero on any mismatch. It does not connect to any production data source.

What a receipt proves
A signed receipt proves what blueRecall ran and recorded; it does not prove an underlying real-world claim is true. Anyone can check the signature offline with the standalone verifier shipped alongside the product, without installing blueRecall itself.

FAQ
Does blueRecall make the decision for me?

No. No automatic deletion, retraction, notification, or production-system write, and no claim that an unaffected result is scientifically true.

Does blueRecall replace the system I already use?

No — it is an overlay. Your existing record system, LIMS, or claims platform stays exactly where it is.
