blueHealthcare launcher & platform

The launcher is the single window a clinic or reviewer opens: one login, a product switcher, and a reverse proxy in front of each entitled product — never a separate URL or install per product.

What this is and is not

The launcher itself makes no clinical or claims decisions. It authenticates a named user, decides which products that install is entitled to run (via a signed, offline-verifiable entitlement file), and proxies requests to each product's own process. Every product keeps its own database, its own tests, and its own decision boundary — the launcher depends on the products; no product depends on the launcher.

Who uses it

An operator (installs and licenses the suite for a site) and named end users with roles — reviewers, adjusters, lab staff — each seeing only the products their entitlement and role permit.

Getting started — demo only

The commands below start the local demo, not a production deployment. Run from ~/products/blueHealthcare/launcher:

make install        # backend deps
make web-install     # frontend deps
make demo            # mints a demo entitlement for all 7 products, starts the launcher

The demo prints its login (a demo username and password) on start. make demo-two starts the same launcher with only two products entitled, to see the switcher change what's visible.

What a receipt proves
The launcher's own audit log is hash-chained and checkpointed daily with a signature, so tampering with history is detectable. This proves what happened in the log — it does not itself certify any clinical or claims outcome; that boundary belongs to each product's own signed receipt.
Known gaps, stated plainly
  • Care-team-scoped access control covers a subset of clinical record types today, not all of them (see the security page).
  • The suite composes 13 planned modules; several are still design-only or early build. This manual and the product list on this site describe only what exists in code today.
  • No production deployment exists yet — everything above describes the local demo.
FAQ
Does the launcher replace our EHR?

No. It is an overlay that runs alongside your existing systems and produces independent, signed review records.

Does opening a product in the launcher change who is responsible for the decision?

No. A named human remains the only decision authority for every product in the suite, regardless of how it's launched.
