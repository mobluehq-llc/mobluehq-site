The mechanism

How a country becomes a pack

blueHealthcare is built so that a country is a configuration pack — never a fork. This page describes what that means today, precisely, including what is not true yet.

InternationalGermanyAustraliaSaudi ArabiaUnited KingdomThe pack model
What exists in code today

A jurisdiction-neutral interface (JurisdictionPack, plus three pluggable Protocols: CodingSystem, PrivacyRegime, FhirProfile) with 17 fields covering coding, privacy, FHIR profile, compliance-rule identifier, policy-pack format, payer vocabulary, currency, locale, date/number format, data-residency flags, and five additional consent-related fields. See the full field list on the pack spec page.

Two packs are registered: us (real — the only pack any code path uses today) and xx (a deliberate, empty non-US stub proving the interface doesn't assume a US answer). The loader refuses an unknown pack id outright — there is no silent fallback to us.

What this does not mean yet

We do not say "switch the pack and it runs in Germany." That would not be true. Here is the measured state instead:

  • Exactly one place in the codebase resolves a jurisdiction pack today: the consent gate (core/consent/gate.py), which loads a record's own pack to answer a single question — is secondary use allowed under that record's jurisdiction.
  • The rest of the platform's core still reads US-specific constants directly rather than through a selected pack. A standing test greps for exactly that and is deliberately red on purpose: as of the product's own tracking, it finds 61 US-only tokens outside the one directory allowed to hold them (core/jurisdiction/us/) — unchanged across at least two build lanes.
  • A second standing test measures the dependency count from the platform's core to its application layer: 115 such dependencies exist today, also unchanged across at least two build lanes, and also a known, open gap rather than a finished boundary.
  • The addendum's own required demonstration — "switch to the xx stub pack and boot the app with no US strings visible" — is not reachable yet, for the same reason: there is no boot path that reads from a selected pack.

We publish the migration counts, not a finish date.

What "anywhere" means, mechanically

Adding a new country means a new directory under core/jurisdiction/<xx>/ implementing the three Protocols and the 17 fields, then registering it by id in the pack registry. An unregistered directory does nothing — there is no filesystem-scanning magic, so a half-built pack can't silently activate.

This page describes website-depth requirements only, drawn from public information about each market. It is not legal advice, not a compliance claim, and not validated in-country. Nothing here has been reviewed by local counsel or a local regulator. The interface existing is not a claim that migration is finished, and no country is "supported" until its own page here is updated by a named steward, never by a lane's own say-so.
