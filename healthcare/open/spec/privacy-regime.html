The PrivacyRegime protocol

Open — homeWhyArchitectureSpecContributeFixturesGovernanceSecurityRoadmapCommunity

A jurisdiction's privacy-law posture — consent text, retention defaults, and export rules — addressed by jurisdiction-neutral scope/purpose/resource-type names, never by one regime's own vocabulary.

regime_id() -> str
    # A short identifier. Never used by core for branching logic — core reads the
    # regime's answers, never its identity.

consent_text(scope: str) -> str
    # Patient-facing consent language for a named scope (e.g. "clinical_use",
    # "secondary_use", "research"). No text for a scope returns "", never None.

retention_default_days(resource_type: str) -> int | None
    # Default retention in days for a FHIR resource type, or None if this regime
    # declares no default (silence is data, not a defect).

export_rule(purpose: str) -> str
    # A short, human-readable statement of what this regime requires before data
    # leaves the institution for `purpose`. Not machine-enforced by this Protocol
    # alone — the consent gate and de-identifier are the enforcement points.

The US pack's current implementation carries HIPAA-shaped text. GDPR, PIPEDA, and the Australian Privacy Principles are named slots, not implementations, in the interface itself. Retention values are labelled PLACEHOLDER even for the US pack today.

This page describes website-depth requirements only, drawn from public information about each market. It is not legal advice, not a compliance claim, and not validated in-country. Nothing here has been reviewed by local counsel or a local regulator.
