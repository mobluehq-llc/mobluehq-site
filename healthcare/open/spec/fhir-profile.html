The FhirProfile protocol

Draft — v0.1
Open — homeWhyArchitectureSpecLicensingContributeFixturesGovernanceSecurityRoadmapDownloadsCommunity

The FHIR R4 profile switch. R4 itself is the fixed interchange baseline — only the profile varies by jurisdiction, never the FHIR version.

profile_id() -> str
    # A short identifier, e.g. "us-core". Never used by core for branching logic.

profile_url(resource_type: str) -> str | None
    # The StructureDefinition canonical URL this profile declares for
    # `resource_type`, or None if this profile doesn't constrain that type.

The US pack's current implementation selects US Core. UK Core, AU Base, and IPS are named profile slots, not implementations, in the interface itself — each would need one fixture proving the switch works before it's real.

This page describes website-depth requirements only, drawn from public information about each market. It is not legal advice, not a compliance claim, and not validated in-country. Nothing here has been reviewed by local counsel or a local regulator.
