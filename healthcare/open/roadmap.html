Roadmap

What's built, what's measured, what isn't

Open — homeWhyArchitectureSpecLicensingContributeFixturesGovernanceSecurityRoadmapDownloadsCommunity

This page mirrors the platform's own named-gaps tracking, in plain words. See the commercial suite's status page for the per-product met/not-met/not-measured counts — this page is about the shared spine underneath them.

Built and falsified
  • The jurisdiction-neutral pack interface (17 fields, three Protocols) and two registered packs (us real, xx a deliberate empty stub).
  • A consent gate that reads a record's own pack to decide whether secondary use is allowed — the one real caller of the pack loader today.
  • A capture-gating mechanism that refuses to enable without a valid, unexpired, jurisdiction-matched approval, and an exporter that never returns a raw record.
  • A standing scanner that fails the build if a surface for exchanging patient records for money — in any shape — is added anywhere in the codebase.
  • A community build (make community): an image containing only the free edition's modules, with a test proving the commercial ones are absent from the artifact, not merely switched off.
Measured, still open
  • A batch of US-only tokens remain outside the one directory allowed to hold them — a standing test is deliberately red until they're migrated. (This page used to quote a specific count; it had drifted by one when it was checked again days later, because the count never said what token shape it matched or when it ran, so the number is removed until the test states its own methodology.)
  • 28 production-code dependencies run from the platform's core into its application layer — the one figure that's held stable across every recent recount. The broader total (which also counts test-only imports and sys.path entries) has been reported as 115, as 118, and separately as 110 imports plus 9 sys.path entries, all within the same week — so this page states only the stable figure. A standing test is deliberately red until the production boundary closes.
  • No i18n scaffold exists in either web application yet, and the product stays English-only until it does and a language has a named clinical reviewer signed off — glossary work can start as text now; string files wait for the scaffold.
  • The published community-build images are single-architecture (arm64 only) even though the publish script declares both platforms — its build fallback silently produced single-arch. Most clinic servers are x86-64 and could not run them today.
  • The openmrs/ integration slot named in the addendum has not been created.
Not started
  • A chosen licence and inbound contribution terms (counsel's decision).
  • A public repository of any kind.
  • A funded community-edition maintainer.
Every number on this page is measured against the platform's own tests and tracking files, not estimated. Where a lane's own file doesn't state a number, this page doesn't invent one.
